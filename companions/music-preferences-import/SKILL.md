# 音乐偏好歌曲筛选

把用户当作不熟悉电脑操作的人。先自动检查本机网易云、QQ 官方客户端及可用缓存，不先索要分享链接、数字 ID、密码、Cookie 或新 API Key。用 `--provider auto` 分平台执行；平台 ID 不混用，一方不可用不阻塞另一方。

多账号缓存先观察当前客户端身份，再填写内部 `--verified-nickname/--verified-qq-account`，不能选第一条。网易云 macOS 本地红心和近 30 天去重历史已有实测；QQ 本地仅明确关系 schema 可读、原生未实测。未知分组、加密数据库或缺客户端保留不可用状态；Windows 本地读取尚不支持。不能按歌数猜红心，不把缓存当登录证明或全设备历史，不把近期行数/平台分数当播放次数。

先用视频核心或宿主语言能力扩展并复核词族，将确认的 `forms/related` 写入工作区词表 JSON。用户无需处理这些内部步骤。纯字符串 CLI 输入只匹配所列形式，不能说已自动覆盖派生。通用 `test_words.json` 仅用于试验，不是学生近期词表。

读[运行说明](README.md)，从本技能目录执行 `run_music_trial.py --provider auto --words <词表JSON> --output <工作区新目录>`。相邻视频核心、包内 core、源码核心自动定位；首次在其他宿主读[自适配提示词](adapters/bootstrap.md)，按实际工具能力运行，不能假装有搜索或客户端控制工具。

按红心/近期线索找歌手，再从有英文文本证据的偏好歌曲扩展作品；新候选不继承红心状态。标题仅作召回线索；只计歌词正文实际原词、屈折和确认派生。语言、语境、录音完整性、演唱难度和播放状态分别复核，试算保持 `ready_to_deliver=false`，不当作已核验推荐。

缺少数据时，先由宿主打开官方客户端，让用户正常登录/同步后再试；仍不可读则报告具体缺项，不要求新手处理内部 ID。当前不自动扫码。真实偏好输出留在调用工作区，不导出完整歌词、不发布个人数据，不发送或调度。可用 `demo.py` 做不读账号的离线合成演示。
